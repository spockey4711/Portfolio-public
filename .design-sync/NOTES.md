# design-sync notes — Portfolio Design System

Repo-specific gotchas for future syncs. Read before re-syncing.

## This repo is a Next.js app, not a published package

There is no `dist/` and no `node_modules/portfolio`, so the converter runs in
**synth-entry mode** driven by three things that must stay in the config/CLI:

- `--entry ./.design-sync/entry.ts` — a committed file re-exporting the 6
  `components/ui` primitives. It exists ONLY so `PKG_DIR` resolves to the repo
  root (the build walks up from the entry's dir to the first `package.json`
  with a `name`). Without `--entry`, the build looks for
  `node_modules/portfolio/package.json` and crashes (ENOENT).
- `componentSrcMap` enumerates the 6 primitives with their src paths. Discovery
  needs it because synth mode has no built `.d.ts` to scan.
- `dtsPropsFor` hand-writes each component's props body. In synth mode ts-morph
  parses 0 `.d.ts` (log: `[DTS] parsed 0 .d.ts files from .../types`), so
  auto-extraction returns the generic `[key: string]: unknown` fallback. The
  hand-written bodies mirror the real source types — **update them if a
  component's props change**.

Build command (from repo root):

```sh
node .ds-sync/package-build.mjs --config .design-sync/config.json \
  --node-modules ./node_modules --entry ./.design-sync/entry.ts --out ./ds-bundle
```

## Styling is Tailwind v4 — CSS is a committed snapshot

Tokens + `@theme` live in `app/globals.css`; utilities are generated by Tailwind
at Next build time. The converter can't run Tailwind, so we ship a **snapshot**
of the compiled output:

- `.design-sync/css/tailwind.css` — copy of `.next/static/chunks/<hash>.css`
  (the prod Tailwind output; carries `:root` tokens + every utility the whole
  site uses, which covers all 6 primitives). `cfg.cssEntry` points at it.
- `.design-sync/media/*.woff2` — the 23 next/font woff2 files the snapshot's
  `@font-face url(../media/...)` rules reference. `../media/` resolves from
  `css/`, so the converter harvests them into `fonts/`.

### To re-snapshot (do this when tokens or component classes change)

```sh
pnpm build   # regenerates .next/static/chunks/*.css
SRC=$(ls -t .next/static/chunks/*.css | head -1)   # hashed filename changes each build
cp "$SRC" .design-sync/css/tailwind.css
# copy the woff2 the css references:
python3 - "$SRC" <<'PY'
import re,os,shutil,sys
css=open(sys.argv[1]).read()
for f in set(re.findall(r'url\(\.\./media/([^)]+\.woff2)\)', css)):
    s=os.path.join('.next/static/media', f)
    if os.path.exists(s): shutil.copy(s, os.path.join('.design-sync/media', f))
PY
```

## Known render warns / overrides

- `SectionHeader`: `overrides.SectionHeader.cardMode = "column"` — its full-width
  divider overflows a normal grid cell. Applied; renders full-width per story.

## Scope

Only the 6 `components/ui` primitives are synced (Button, Card, Divider,
MonoLabel, Pill, SectionHeader). The `sections/`, `chrome/`, `widgets/`,
`legal/`, `seo/` folders are page compositions that depend on Next.js runtime
(next/image, next/link, content data, client reveal scripts) and are
intentionally excluded.

## Re-sync risks (watch-list)

- **CSS/font snapshot staleness.** `.design-sync/css/tailwind.css` and
  `.design-sync/media/` are a point-in-time copy of the Next build output. They
  go stale if: a design token changes, a primitive starts using a new utility
  class not already emitted elsewhere on the site, or next/font / Next.js is
  upgraded (woff2 hashes change). Re-snapshot (above) whenever that happens —
  nothing downstream will warn you if a class is missing.
- **`.next` filename is hashed** — the re-snapshot must glob `*.css`, never a
  pinned name.
- **`dtsPropsFor` is hand-maintained** — drifts silently if source props change.
- Google Fonts (OFL) are committed under `.design-sync/media/`; fine to ship.
